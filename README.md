# java-racingcar-precourse

## 2주차 컨셉

- 1주차와 동일한 점
    - 5시간 제한을 둔다.
    - PM과 개발자의 자아를 오고 간다.
    - '요구사항 분석 -> 테스트 기반 개발 -> 리팩토링' 흐름을 지킨다.
- 2주차의 새로운 점
    - 브랜치를 초기화하지 않는다.
    - '진상 클라이언트'의 자아를 추가한다. (아이디어는 [`feedback.md`](./docs/feedback.md) 참고)
        - 갑작스럽게 요구사항을 추가하거나, 기존의 가정을 뒤엎는다.
        - 이런 저런 이유로 코드에 트집을 잡는다.

### 문제 풀이 방식

- 매일의 개발을 `origin/develop` -> `trial/day-{n}` 브랜치에서 시작한다.
- 5시간의 제한 내에 각 회차의 시도를 마무리한다.
- `develop` 브랜치에 회고 PR을 남긴 후 병합한다.
    - git-flow 설정 `oomia` - `develop` - `trial/day-{n}`
- 각 PR은 다음 내용을 포함한다.
    1. 진상의 행동
    2. 그에 대한 대응
    3. 기존의 타임라인 정리
